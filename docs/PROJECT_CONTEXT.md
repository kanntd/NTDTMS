# NTD TMS Project Context

เอกสารนี้ใช้เป็นจุดเริ่มต้นสำหรับผู้พัฒนาและ Codex เมื่อเปิดงานจากเครื่องหรือแชตใหม่ รายละเอียดเชิงสถาปัตยกรรมอยู่ใน `docs/architecture.md` และขั้นตอนระบบ production อยู่ใน `docs/operations.md`

## เป้าหมายระบบ

NTD TMS เป็นระบบบริหารงานขนส่งภายในของ NTD Logistics ใช้พร้อมกันหลายสาขา หลายพนักงาน และหลายเครื่อง งานหลักต้องเร็ว ใช้ง่าย และไม่ทำข้อมูลที่พนักงานกำลังกรอกสูญหาย

เทคโนโลยีหลัก:

- React + Vite + TypeScript
- Supabase Auth, PostgreSQL, RLS, RPC และ Realtime
- Cloudflare Pages สำหรับ frontend และ Pages Worker/R2 สำหรับไฟล์
- สถาปัตยกรรม Modular Monolith บนฐานข้อมูลเดียว

## Workflow ธุรกิจหลัก

1. **รับสินค้าและเปิดบิล**
   - ค้นหาผู้รับก่อน แล้วแสดงผู้ส่งที่เคยจับคู่กับผู้รับ
   - สาขาปลายทางมาจากค่าเริ่มต้นของผู้รับ แต่แก้ได้
   - สินค้าและราคาต้องอ้างอิงคู่ `ผู้รับ + ผู้ส่ง + สินค้า + หน่วยนับ`
   - รองรับเงินสดต้นทาง เงินสดปลายทาง เครดิตต้นทาง และเครดิตปลายทาง
   - รองรับรายการที่ยังไม่ทราบราคาและส่งคำขอราคา

2. **จัดของขึ้นรถ**
   - เลือกสาขาปลายทาง ตรวจยอดบิล จำนวนสินค้า และยอดเงินก่อนสร้างเที่ยวรถ
   - บิลหนึ่งใบแบ่งขึ้นรถได้หลายเที่ยว แต่บิลเดียวกันห้ามซ้ำในเที่ยวเดียวกัน
   - พิมพ์หรือสแกนเลขท้ายบิลได้ โดยระบบเติม prefix ของสาขาและปี
   - ปิดเที่ยวและพิมพ์ใบคลุมรถได้

3. **สาขาปลายทางรับรถ**
   - สาขาเห็นเฉพาะรถและบิลของสาขาตัวเอง ยกเว้น admin/owner
   - เมื่อรับรถ บิลและจำนวนสินค้าที่มากับรถจะเข้าคิวงานของสาขา

4. **กระจายและส่งสินค้า**
   - พนักงานพิมพ์หรือสแกนเลขบิลเพื่อเลือกต่อเนื่องได้
   - รองรับส่งเต็มบิลและส่งบางส่วนตามจำนวนที่อยู่สาขา
   - บิลคงเหลือต้องอยู่ในคิวจนกว่าจะส่งครบหรือตีกลับ

5. **เก็บเงินและวางบิล**
   - เงินสดปลายทางเก็บเมื่อส่งสินค้าและติดตามยอดค้างแยกต่างหาก
   - เครดิตต้นทางและเครดิตปลายทางรวบรวมบิลเพื่อวางบิล โดยค่าเริ่มต้นเป็นรอบสิ้นเดือน
   - รองรับหัก ณ ที่จ่าย 1% แบบเลือกใช้ ไม่มี VAT ใน workflow ปัจจุบัน

## ข้อมูลหลักและราคา

- ผู้รับและผู้ส่งใช้โครงสร้าง party เดียวกัน แต่มีหน้าจอและกฎบังคับกรอกตามบทบาท
- ผู้รับบังคับชื่อ จังหวัด และสาขา; ผู้ส่งไม่บังคับจังหวัด
- ถ้าผู้รับไม่มีอำเภอ ให้ใช้ `เมือง` เป็นค่าเริ่มต้น
- สินค้าเป็น master กลาง ไม่สร้างชื่อสินค้าซ้ำตามผู้รับหรือผู้ส่ง
- หน่วยนับเพิ่มและแก้ไขได้
- ความสัมพันธ์ผู้รับ-ผู้ส่ง และสินค้าของคู่ลูกค้าลบได้โดยไม่ลบ master ต้นฉบับ
- ราคามาตรฐานเก็บเป็นเวอร์ชันและไม่แก้บิลย้อนหลัง
- ส่วนลดเฉพาะบิลไม่เปลี่ยนราคามาตรฐาน
- ราคาที่ปลายทางเก็บได้จะเสนอเป็นราคามาตรฐานใหม่เฉพาะกรณีต้นทางไม่ได้ระบุราคา และต้องผ่านผู้มีสิทธิ์ยืนยัน

## หมายเลขเอกสาร

เลขบิลประกอบด้วยรหัสสาขา ปี พ.ศ. สองหลัก และ running number แบบ atomic ตัวอย่างสาขา `B01` ปี `26` ได้รูปแบบ `B0126xxxxxx` การออกเลขต้องทำในฐานข้อมูลเพื่อรองรับหลายเครื่องพร้อมกัน

## สิทธิ์และขอบเขตสาขา

- พนักงานทั่วไปผูกกับสาขาและเห็นข้อมูลปฏิบัติการของสาขาตนเอง
- admin/owner ดูข้ามสาขาได้ตามสิทธิ์
- สิทธิ์เข้าโมดูลเก็บแยกจากข้อมูลพนักงานใน `module_permissions`
- ชื่อผู้เปิดบิลมาจากผู้ใช้ที่ login โดยแสดงชื่อเล่นถ้ามี และแก้ได้ตามสิทธิ์

## หน้าจอหลัก

- ภาพรวมกรุงเทพ
- รับสินค้าและออกบิล
- ค้นหาและติดตามบิล
- งานขึ้นรถและเที่ยวรถ
- ภาพรวมสาขาปลายทาง
- งานส่งสินค้า
- เก็บเงินสดปลายทาง
- ลูกค้าและคู่ค้า / ข้อมูลหลัก
- ราคาและคำขอราคา
- รายงานและตั้งค่าบริษัท

## หลักการด้านประสิทธิภาพ

อ่านและทำตาม `AGENTS.md` ทุกครั้ง การบันทึกต้องตอบสนองเร็ว อัปเดตเฉพาะข้อมูลที่เปลี่ยน ห้าม refresh ทั้ง workspace โดยไม่จำเป็น และ Realtime จากเครื่องอื่นต้องไม่ล้างฟอร์มที่กำลังกรอก
